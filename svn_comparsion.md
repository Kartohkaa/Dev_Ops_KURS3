# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN - "дорогое"?

В Git ветка - это просто указатель на коммит. Создание ветки происходит мгновенно и не требует копирования файлов. Вся история уже хранится локально, поэтому новая ветка - это просто ссылка на определённое место в истории.

В SVN ветка - это полная копия директории на сервере. Когда создаёшь ветку, система копирует все файлы проекта в новую папку. Для больших проектов это занимает время и место на диске. Плюс нужно подключение к серверу.

В докладе, например, говорится что у них одновременно живёт 8-10 минорных веток, и они выпускают патчи ежемесячно. С такой нагрузкой "дорогое" ветвление SVN просто не справилось бы.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя.

В SVN вся история хранится на центральном сервере. Локально у тебя только рабочая копия - снимок одной версии файлов. Коммит в SVN - это отправка изменений на сервер, поэтому без интернета он невозможен.

В Git по другому - полная копия репозитория лежит у тебя локально. Коммиты делаются локально, а интернет нужен только для push/pull.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

Из доклада можно выделить такие сценарии:

**Legacy-проекты:**
Если компания использует SVN много лет, миграция на Git может быть дорогой и рискованной. Команда привыкла к workflow, всё работает, зачем менять?

**Проекты с жёстким контролем доступа:**
SVN позволяет настраивать права доступа к отдельным директориям. В Git такое сделать сложнее.

**Работа с большими бинарными файлами:**
SVN не требует хранить полную историю всех файлов локально, в отличие от Git. Для проектов с большим количеством бинарников это может быть удобнее.

Но в целом, Git стал стандартом для современной разработки, особенно когда нужно поддерживать много версий продукта одновременно.
